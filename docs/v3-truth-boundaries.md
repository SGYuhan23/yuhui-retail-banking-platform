# V3 事实边界

渝惠是个人学习 / 产品实践项目，非任何银行内部或官方系统。所有 V3 客户、商户、交易、预算成本和经营结果为 Synthetic / Mock Data。未访问银行内部数据，未接真实账户、商户、支付、收单或清结算。

## 真实实现
Spring Boot 2.7 / Java 17、MySQL、React / Umi / Ant Design。旧链运行 Redis/Redisson、RabbitMQ confirm/return、业务幂等、库存预扣、消息任务补偿、Alias Method、DB-Router 和 ZooKeeper DCC。旧链十组回归结果见 verification/public-release/legacy-regression.json。

V3 使用同一个 Spring Boot 进程和 MySQL，单库事务实现权益、积分模拟扣减、库存、预算流水和经营事件的一致落库。沿用原本地 JDBC 权益台账与唯一键防重设计，新增历史条款和商户范围；没有谎称新券预算通过 MQ 异步记账。

## 未启用或不主张
Dubbo 依赖仍会初始化配置，但 local 注册地址 N/A，未验证服务间 RPC；Nacos、Canal/Elasticsearch 同步、XXL-JOB 调度中心均未作为当前运行能力。分库组件是 DB-Router，不是 ShardingSphere。没有生产容量、高可用、多实例故障恢复或金融合规认证结论。

## P0 限制
- 回环地址和 local profile 限制；固定本地管理员，SYN 客户可切换。没有生产认证、真正双人复核或多用户 RBAC。
- V3 合成积分余额独立于旧账户 10002，避免 Reset 清理原历史数据；两类权益在现有 Wallet 页面分别呈现，未迁移旧权益到 V3 预算。
- 一个方案一个场景、一种权益、一个冻结客群、多家商户。多批次模型存在，默认整额分配给一个批次，没有复杂的批次预算拆分 UI。
- 新券主线支持 COUPON 和 POINTS_EXCHANGE；DRAW_REWARD 类型保留在目录，抽奖使用旧营销玩法，不把历史抽奖虚构成 V3 投放事实。
- 有效期释放是每分钟任务，可手动触发；没有跨实例生产调度治理。每次领取占用发行库存，取消/到期不回补；单客领取次数不因取消重置。
- 历史库触发器防应用层改写，不抵御拥有 DDL 权限的数据库管理员。Reset 是显式管理操作，删除 V3 演示历史。
- 演示使用固定 2026-10-01 基准日，last_active_days 是当时标签；新活动时间需覆盖当前操作时间。已结束固定案例用于复盘，不可继续领取。
- 目标行为是核销后的独立模拟观察；只表示相关事实，不表示增量活跃或营销因果效果。没有 ROI、收入增长、NPS 或虚构 A/B。
- 原 app/src/test 中的课程样例依赖非 local 环境（ES/Dubbo 等），原 Maven 配置跳过；本次显式运行可执行 V3 单元测试和原本地集成脚本，不将被跳过的课程样例计为通过。

## FINAL PATCH 事实口径

目标达成率 149.3% 仅为当前固定种子合成案例的目标完成比例，不是实际银行业务完成率，也不是营销归因或唤醒增量。目标观察窗口等于冻结 Run 时间窗口（含边界）；窗口后核销/到期属于累计履约，成本在待履约权益全部终态前仍可能变化。review_as_of 使用 Asia/Shanghai 本地时间。

复核完整性保证规则/执行配置与批准一致，不提供真实双人认证。提交冻结规则，发布冻结当时成员；手工 Snapshot 不自动成为活动发布 Snapshot。数据库管理员直接 DDL/DML 不在防篡改威胁模型内；验收中直接 SQL 修改草稿预算、插入窗口外事件、提前权益到期是明确测试夹具，随后 Reset 清除。

保留 P2：NEW 标签仍按 last_active_days<7；历史商户展示名未全部冻结；无样本拆解百分比仍可显示 0%；未重做 DDD、消费者首页、多批次配置 UI。上述为当前实现边界。
