# V3 Demo 操作与 3 分钟演示

## 启动 / 重置
在仓库根目录执行 `./scripts/start.sh`。已有构建可加 `--no-build`。启动应用会增量执行 06-v3-operating.sql；首次演示执行 `DEMO_SEED=202610 python3 scripts/reset-demo-data.py`，或者系统配置 → 演示数据 → 重置。

重置会清空 V3 用户操作数据，不清空原积分和抽奖记录。固定种子产生 30,000 客户、12 商户、4 场景、3 权益类型、4 客群、1 个已结束案例。默认案例 2,166 人快照、1,563 人触达、964 人参与、500 人领取、275 人核销、224 人目标行为；银行实扣 3,300 元、释放 2,700 元，商户让利 2,200 元。数字来自实际执行及流水聚合。

## 完整操作路线
1. 打开 http://127.0.0.1:18000/operating/overview。
2. 客群经营 → 沉默高积分客户 → 编辑 / 预览，查看条件、人数及分布；冻结快照并查看成员。
3. 活动经营 → 新建经营方案。设置客户唤醒、该客群、社区生活、20 元券、8 家社区商户、600000 分预算（6000 元）、硬上限、目标行为和起止时间（覆盖今天）。保存草稿。
4. 提交复核 → 通过 → 发布冻结版本；发布版本页查看配置 → 创建投放批次。
5. 批次页执行模拟投放，选择快照客户。记录触达、参与；选择商户并领取。或者消费者首页 `/experience?customer=SYN00037` 切换该合成客户，选择商户领取。新批次内该客户必须是快照成员。
6. 钱包 `/wallet?customer=SYN00037` 查看有效期、适用商户、最低消费及 YH-批次-SYN… 模拟码。
7. 商户与权益 → 商户模拟核销 → 输入码 → 查询 → 选择同一商户 → 输入达到门槛的模拟消费金额（分）→ 核销。再次核销不能成功。
8. 活动批次页单独记录预定义目标行为；它不由核销自动生成。查看经营复盘的领取/核销/目标行为和预算变化。
9. 结束批次；复盘按商户切换，填写原因，选择扩大/保持/减少/停止，保存指标快照。
10. 未使用权益到期后每分钟自动释放预算；可以点击总览“释放已到期权益预算”。手工取消也会释放；不能用此按钮提前使尚未到期权益失效。

## 3 分钟录屏点击顺序
- 0:00–0:20：经营总览，说明个人模拟项目，核心问题是预算如何落实到客户及商户场景。
- 0:20–0:45：客群经营，展示规则预览、快照人数和冻结属性。
- 0:45–1:10：活动方案及发布版本，说明目标、权益成本分担、硬预算和复核。
- 1:10–1:50：使用预先建好的运行批次，消费者领券 → 钱包复制码 → 商户核销；说明预占转实扣。
- 1:50–2:35：切换已结束固定案例，展示漏斗、成本、预算流水以及商户核销差异。
- 2:35–3:00：人工记录下一轮减少低核销商户额度，说明数据与结论边界。技术作为预算不超发、履约不重复的支撑。

录制前准备好两个标签页及一个运行批次；不要用已结束固定案例再次领取。新建批次仅改变自己创建的案例，不改变固定历史案例指标。

## FINAL PATCH 演示补充

1. 活动方案提交后打开「查看提交复核快照」，展示规则与 SHA-256，再批准发布。批准后编辑关联 Segment 规则，发布会提示 REVIEW_CONTENT_CHANGED 并退回草稿；重新提交/批准后再发布。
2. 创建批次默认分配整个活动上限，重复创建提示累计额度不足。多 Run API 定向测试展示总额 6000、硬上限 2400 无法绕过（测试金额单位分）。
3. 固定案例复盘展示 224/150、+74、149.3%、已达标，说明这些是合成观察事实。目标窗口内去重，核销/成本为截至当前累计履约。原漏斗 2166→1563→964→500→275→224、实扣 3300 元、释放 2700 元、商户让利 2200 元不变。
4. 结束有未核销券的批次，复盘提示「投放已结束，权益履约仍在进行中」；仍可保存阶段决策。后续核销/到期改变累计成本，但历史决策指标快照不变；全部权益终态后展示履约已完成。
