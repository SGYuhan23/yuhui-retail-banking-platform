# 当前工程边界

## 模块及依赖方向

- `runtime`：应用启动、Spring 组件装配和环境配置。
- `entrypoints`：HTTP/MQ/调度入口及冻结的 `com.yuhui.operating` 经营用例。保留 V3 的 JDBC 事务组织。
- `marketing`：积分、抽奖、奖励、参与额度、任务；声明业务存储端口。
- `storage`：MyBatis、Redis、消息发送及业务端口适配。
- `contracts`：既有管理/营销 API 契约与 DTO。
- `readmodel`：管理查询契约；保留其与写模型的独立依赖边界。
- `shared`：响应、事件、异常和通用基础设施类型。

不是重新发明七层架构：现有 Maven 依赖边界保留；职责划分涵盖领域包位置、模板继承消除、窄存储端口、投递编排和事务后消息处理的职责分离。

## 兼容性

HTTP 路径与请求响应不变；数据库表/列/索引/触发器和 SQL 不变，无新增 schema migration。RabbitMQ 队列、Redis key、分库路由、账号语义保持兼容，避免旧余额、任务、缓存失联。公开版 Compose 项目名为 `yuhui-retail-banking-platform`，使用独立本地卷；新工程的目录与运行应用名均为渝惠。

Redis JSON 保存过类名；LegacyCacheTypes 仅在读取时映射历史类型，新写入使用新 package。必须先停旧服务，再启动新服务；不支持在共享缓存上混跑新旧后端，因为旧程序无法读取新类型。回滚应使用匹配版本的本地数据备份，不能直接混用。

## 原子性与错误语义

行为奖励仍将同一行为的多项奖励与 outbox 一次落库；已领取赠礼抛出原错误，普通行为保留跳过逻辑。空批次仍由仓储按原规则拒绝。参与/额度交易保留账户锁、路由、事务、唯一键和异常代码。库存预占与异步回写独立于账户账本端口。

TaskService 负责待投递批次的确认/完成/失败顺序；定时入口仅持有跨分片锁及路由生命周期。CommittedOutboxDelivery 只在业务提交后尝试投递，失败标记任务待补偿，不撤销业务事实。SQL 与方法内部算法保持原行为，兼容性重构不改变库存或记账。
